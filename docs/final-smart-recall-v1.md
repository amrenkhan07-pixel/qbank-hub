# Final Smart Recall v1 and study continuation

1. **Existing architecture reused.** Smart Recall already selected importance/mistake/saved/due buckets; finalized `pyq_concept_importance` supplies exam importance; `smart_recall_concept_coverage` records successful concept coverage. Universal `user_question_state`, `bookmarks`, SRM functions and saved QBank session tables remain authoritative.
2. **Files changed.** `app/app.js`, `app/smart-recall.js`, `app/smart-recall-model.mjs`, `app/smart-recall-data.mjs`, new `app/smart-recall-preferences.mjs`, `index.html`, `scripts/final-smart-recall-test.mjs`, `scripts/final-smart-recall-transaction-tests.sql`, this report, and the migration below.
3. **Schema.** Migration `20261004203234_final_smart_recall_preferences_and_study_context.sql` adds three fields to existing `user_srm_settings`: saved Recall preferences, a revision counter, and pending rotation notices. Five authenticated, security-invoker functions provide preference saves, coverage summaries, bounded personal candidates, candidate coverage labels, and QBank continuation. No new table, source-data write, or index is needed. Existing owner RLS applies; stale cross-device saves are rejected.
4. **Selection priority.** Personal buckets reserve their useful candidates first. Repeated HIGH-importance mistakes lead the mistake pool, followed by repetition, importance and recency. GI exposure uses uncovered tiers and least-recent exposure, then deterministic daily variation. Subjects are interleaved within a tier; a large subject cannot dominate by row count alone. The active/early 60/40 split remains a target with useful fallback.
5. **Learning states.** Unseen means no saved Recall exposure. Seen/Weak means assigned but no successful submitted answer. Covered means at least one submitted correct Recall answer, as in the existing coverage implementation. Due Again comes from the universal SRM due timestamp. Historical coverage does not erase current personal weakness. SURE has stronger scheduling evidence through the existing longer intervals; viewing or answering incorrectly never creates successful coverage.
6. **Tier progression.** Each subject advances from uncovered HIGH to MEDIUM to LOW. Once all eligible tiers are covered, least-recent exposure drives revision. Early Exposure additionally rotates completed HIGH/MEDIUM subjects when useful replacements exist. Deliberately pinned or temporarily focused subjects may continue to LOW/revision.
7. **Mistake override.** Covered concepts remain eligible through universal Incorrect or due revision. Incorrect and repeated mistakes are not blocked by the GI coverage filter. Existing SURE/UNSURE scheduling is preserved, including progressive intervals. The optional AGAIN control was not added because the existing scheduler has no dedicated Again event; it was not reinterpreted as an incorrect answer or reset.
8. **Deduplication.** Every canonical question ID appears once in a plan; all qualifying reasons are combined. GI supplies at most one question per finalized subject/concept ID and avoids concepts already reserved for personal revision. Families are optional. No semantic matching or question duplication was introduced.
9. **Universal Incorrect.** Both normal QBank and Recall continue through `qbank_record_attempt_v2` into the same `question_attempts` and `user_question_state`. The new bounded candidate query consumes this aggregate state directly; no Recall-only Incorrect collection exists.
10. **Universal Bookmark.** Existing `qbank_set_bookmark` updates both universal representations. Recall consumes the same state. Addition and removal were tested. No bookmark history was rewritten.
11. **Universal Mark for Review.** Recall consumes `marked_for_review`/`revision`. Resuming an old session now respects current universal state rather than resurrecting a historical session mark. Legacy `revision` flags also display consistently. No separate Recall collection was created.
12. **Active persistence.** Active subjects sync in `user_srm_settings.smart_recall_preferences`. Cloud settings outrank a device cache; a first-use device preference is imported once. Active subjects change only through an explicit save, never through rotation.
13. **Early persistence.** Early subjects sync in the same account settings, including automatic replacements and deliberate manual pins. Settings survive browser reload and apply on other devices signed into the same account.
14. **Auto-rotation rule.** When an Early subject has zero uncovered usable HIGH and MEDIUM concepts, replace it only if another eligible subject has uncovered HIGH/MEDIUM and the original subject is not deliberately pinned. Never replace an Active subject. No eligible replacement means the selection remains intact.
15. **Replacement choice.** Exclude current Active/Early subjects and exhausted subjects. Prefer subjects with uncovered HIGH, then the lowest proportion of HIGH/MEDIUM already covered, least-recent exposure, more uncovered HIGH, and stable subject-name tie-breaking. No pure random subject replacement is used.
16. **Visible changes.** A concise “Early Exposure updated … Switched to …” notice appears in Recall Today and is saved until dismissed. Auto-rotation requires no confirmation. A compact expandable coverage display shows HIGH/MEDIUM covered totals.
17. **Manual and temporary focus.** Explicitly selecting an already-completed Early subject pins it until the user changes that choice. Subjects selected before completion may rotate after their remaining HIGH/MEDIUM is covered. “Microbiology today” is a separate visit-only selector: every bucket and fallback stays in Microbiology; saved Active/Early settings are untouched. Temporary focus bypasses auto-rotation.
18. **Continue Studying persistence.** An additional Home section uses existing account-owned sessions, frozen question snapshots, filters, position and answers. It selects ordinary QBank context independently of Recall/GT. Every existing Home card remains present. No device-only continuation store or redundant table was added.
19. **Next QBank.** Unfinished ordinary QBank sessions take priority. Otherwise the existing function advances only after the selected source module is actually answered, using matching platform/subject/source path and explicit source sequence. Ambiguous ordering, partial modules and exhausted sequences never produce a fabricated next module. Original question order is untouched.
20. **Daily workload.** The default target is 30. The starting 12/9/5/4 allocation is flexible; useful unused GI, mistakes, saved and due candidates fill shortages without duplicate questions. If fewer than 30 useful questions exist, the UI reports the shortfall. A large overdue backlog does not enlarge the session. Optional +10/+20 completion controls were not added.
21. **Tests.** SQL rollback fixtures passed preference persistence/concurrency/account isolation, bidirectional Incorrect/bookmark/review consumption and removal, wrong-not-covered, bounded windows and coverage summaries. Existing SQL coverage progression and source-order continuation fixtures passed. Browser tests passed Enterobius label timing, server preferences after reload, visible auto-rotation, immutable Active subjects, manual pins, temporary focus, question 23/40 restoration, next-module action, stale review-mark removal, Home-card coexistence and mobile overflow. Model tests passed deduplication, combined reasons, redistribution, subject balance and 30-question cap. Existing timer, Smart Recall allocation and GT rules checks passed. The previously documented GT lifecycle harness failure is unchanged and outside this patch.
22. **Performance.** Personal candidates now come from one bounded server query, at most 90 per personal bucket, instead of transferring every learning-state row and fetching eligibility in client-side batches. The measured database execution was approximately 97 ms on the account with the largest existing aggregate state (not a browser end-to-end timing). GI remains bounded to 50 candidates per subject. No raw-attempt scan or media preloading was added. The existing limited Home accuracy/history query remains unchanged.
23. **Data preservation.** Before/after fingerprints match for all 61,047 questions, 65,998 source occurrences and 5,490 importance entries. Finalized PYQ occurrences remain 5,937. No score, taxonomy, classification, source identity, original ordering, question ID, media or semantic-search changes were made.
24. **GT preservation.** GT implementation files, saved GT state and continuation routes are unchanged. The added normal-QBank card does not select GT sessions. Existing GT timing/rules checks passed; no live user GT was modified for verification.
25. **Home preservation.** Existing Continue, Active Recall, Accuracy, Smart Recall, Weak Areas and navigation cards/links remain intact. Continue Studying is additive. No real user was signed out for testing.
